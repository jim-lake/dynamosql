# @dynamosql/mvcc-index-encode

## Project boundary

The directory containing this `AGENTS.md` is the project root. Never look at
anything outside this directory and its descendants. Keep all searches, reads,
references, and edits within the project. This rule includes parent directories,
sibling packages, and paths reached through links or symlinks.

Ordered byte encoding for DynamoSQL MVCC primary-key and index values. The
encoded bytes are stored in an external system whose only comparator is
bytewise, under a small key size limit. The requirement is order equivalence
with MySQL, not byte equivalence: for any two values, comparing our bytes must
give the same result (less, equal, greater) as comparing MySQL's
`WEIGHT_STRING` bytes. Size matters as much as correctness. The rules below
and the oracle fixtures are the source of truth for this package.

## Status

`weightString` and `canonicalString` are implemented. Other value encodings
(integers, DECIMAL, FLOAT/DOUBLE, temporal types) and the key/index builders are
not written yet. `STRING_ENCODING.md` is the only description of the string
key and framing formats; do not restate them here.

## Rules

- Every collation is NO PAD, including `ascii_bin` and `ascii_general_ci`.
  Nothing pads a value to a declared width, and trailing spaces are significant.
- Collations: only `ascii_bin`, `ascii_general_ci`, `utf8mb4_0900_bin`,
  `utf8mb4_0900_ai_ci`, `utf8mb4_0900_as_ci`, and `utf8mb4_0900_as_cs`. Do not
  add others without an oracle check.
- For `weightString`, the three UCA collations share the weight table in
  `src/generated/uca_0900_as_cs.ts`. The dump checks the active levels against
  MySQL at each strength. For `canonicalString`, the per-strength tables are in
  `src/generated/canonical_0900.ts`. Package size and retained table memory
  take priority over warm-call throughput for this reader.
- Do not rely on the key matching `WEIGHT_STRING` for `as_cs` and `as_ci`.
  The format may change freely. There is no backward compatibility requirement,
  and stored keys need no migration.
- The encoding is not fixed. It may change in any collation at any time, and
  size curves are measurements of the current format, not guarantees.
- `test/storage_sample.test.ts` is the sole exact-byte regression test. Its
  saved storage sample records the value of `STORAGE_VERSION` alongside the
  inputs and their exact encoded bytes for each collation. When the versions
  match, the test must fail on any byte difference. For work that preserves
  the format, keep the version and saved sample intact and fix any unexpected
  difference in the encoder.
- When intentionally changing the ordered-key storage format, increment `STORAGE_VERSION`
  in `src/index.ts`. Keep the existing sample at its recorded version. A
  version mismatch skips the storage sample test on every run until a new
  sample is explicitly saved for the current version. Tests, builds, and
  MySQL oracle regeneration must never refresh or relabel the sample.
- All other encoding tests assert ordering and equality only. Do not pin
  bytes, lengths, widths, cutoffs, or derived maxima such as `maxBytes` or
  witness sizes. Use `expectSameOrder` from `test/order.ts`.
  Hand-written cases use `expectAscending` chains.
- Investigation and probe scripts go under `scripts/`, named for what they
  measure or check (for example `length_model.ts`, not `test1.ts`). Keep them
  there after use. `scripts/` is excluded from `ts:check` (tsconfig) and lint
  (eslint config), so they are not held to the test-code rules.
- Import direction is one way. `src/` imports only from `src/`. `test/` never
  imports from `scripts/`. Code shared by tests and probe scripts goes in
  `test/helpers/`, and `scripts/` may import from `test/helpers/` and `src/`.
- The oracle samples are seeded pseudo-random in `scripts/dump-oracle.mjs`. Add
  a new sample set there when a bug shows a shape it misses.
- Regenerate the tables in `src/generated/` and the fixture
  `test/fixtures/oracle.json` with `node scripts/dump-oracle.mjs` against
  local MySQL 8.4. Do not hand-edit these files.
- A MySQL 8.4 server is always available for oracle dumps and checks. Do not
  treat its absence as a blocker.
- No history in documents. Never tell stories, describe how the code got where it is, or record superseded values, dropped approaches, or earlier measurements. History lives only in git. Every other document states only the present.
- No comments. Do not add function or type doc comments, comments that restate
  the code, or file header comments, except the one-line "Generated by" header
  that generated files carry to mark them as do-not-edit. Add a single-line
  comment only where the behavior is non-obvious, and keep it to what the reader
  needs to know.

## Commands

Run from `packages/mvcc-index-encode/`:

| Task       | Command            |
| ---------- | ------------------ |
| Type check | `npm run ts:check` |
| Test       | `npm test`         |
| Lint       | `npm run lint`     |

For `canonicalString` changes, the MySQL probes check every Unicode scalar and
seeded whole-string families at all three UCA strengths. The offline
minimum-spelling probe checks UTF-8 cost and tie breaks on short symbol streams.

```sh
node --import tsx scripts/canonical_scalar_partition_check.ts
node --import tsx scripts/canonical_family_probe.ts
node --import tsx scripts/canonical_minimum_probe.ts
```
